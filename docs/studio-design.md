# Cellar Studio 设计

> 状态：设计稿（未实现）。配套界面原型见 `studio/prototype/`，截图见 `docs/studio/`。
> 本文回答"Cellar Studio 做成什么样、为什么这样做"；实现顺序与阶段划分见 `docs/ROADMAP.md`。

---

## 1. 定位

Cellar Studio 是 TavernCellar 面向用户的图形界面：**一个窗口完成 连接酒馆 → 浏览资料 → 取出 → 编辑 → 同步 → 处理冲突**，不需要命令行，也不需要另开编辑器。

目标用户是写卡作者，不一定熟悉命令行和 git。会用 VS Code 的用户照样可以只用 VS Code——Studio 和外部编辑器改的是**同一个工作区**，可以混着用。

### 设计原则

1. **工作区是唯一的数据来源。** Studio 不另存一份数据；表单里的每次修改都经伴侣程序编码后写入工作区文件，和 VS Code 里改文件走同一条路。外部编辑器改了文件，Studio 立刻看到。
2. **与酒馆的说法一致。** 字段名称、顺序、默认值、取值范围以酒馆源码为准：角色字段对应 ST 的角色编辑面板，世界书条目对应 `newWorldInfoEntryDefinition`；中文文案沿用 ST 的 `zh-cn.json`（见附录 A）。用户不需要学第二套术语。
3. **绝不静默覆盖，并且看得见。** 每一项在每个酒馆的同步状态始终可见；冲突按字段展示两边的内容，由用户逐项取舍。
4. **常用在前，高级折叠。** 首屏只放写卡最常改的字段；递归、分组、黏性等参数收进"高级"，但一键可达。
5. **长文本优先。** 角色描述、开场白、世界书内容是主体，编辑区要宽、字体可选、有字数统计，切换条目不丢光标与滚动位置。
6. **离线可用。** 没有酒馆连接时照样能浏览和编辑已取出的资料，连上后再同步。

### 不做的事（本设计范围外）

正则与预设（阶段 4）、提示词预览（阶段 5）、MCP（阶段 6）只在导航中预留位置；聊天功能永远不做。

## 2. 形态与进程架构

### 2.1 形态

- **桌面应用**：Electron，双击启动，可最小化到托盘常驻；自带伴侣程序，不需要另装 Node。
- **同一套界面也能在浏览器里打开**：`cellar serve` 之后访问 `http://127.0.0.1:7349/studio/`，供不想装桌面版、或在 Linux/macOS 上先行使用的用户。
- **以后嵌入 VS Code**：同一套界面作为 VS Code Webview（阶段 6，可选）。

三种形态共用一份界面代码、一套伴侣程序 HTTP 接口；桌面版只是多了原生能力（选目录、托盘、系统通知、用外部编辑器打开）。

### 2.2 进程结构

```
┌──────────────────────── Electron 应用 ────────────────────────┐
│ 主进程（Node）                                                 │
│   ├ 伴侣程序：import { startServer } from companion（同一份代码）│
│   │    └ 127.0.0.1:7349  ── /link ◄── Cellar Link（ST / tt 页面内）│
│   │                      ── /api/*、/studio/、/studio/events      │
│   ├ 托盘、单实例锁、自动更新、系统通知                            │
│   └ 原生能力 IPC（选目录、在资源管理器中显示、用外部编辑器打开）  │
│ preload：contextBridge 只暴露上面几个原生能力                    │
│ 渲染进程：BrowserWindow 加载 http://127.0.0.1:7349/studio/        │
│   └ Studio 界面 ── fetch /api/* + EventSource /studio/events      │
└───────────────────────────────────────────────────────────────┘
```

要点：

- **伴侣程序在主进程内运行**，调用现有的 `startServer()`；`cellar` 命令行照常可用，二者不能同时占用同一端口（单实例锁 + 端口占用提示）。
- **界面通过 HTTP 接口与伴侣程序通信，而不是 Electron IPC。** 这样浏览器形态、VS Code 形态完全一致，只有一条通路；IPC 只用于少数原生能力，且浏览器形态下这些按钮降级为"复制路径"等。
- **渲染进程安全设置**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；禁止导航到 `127.0.0.1:<端口>/studio/` 以外的地址，外部链接交给系统浏览器打开。

### 2.3 界面访问伴侣程序的认证

现有 `/api/*` 拒绝任何带 `Origin` 头的请求（防止网页跨站调用）。Studio 运行在浏览器环境里必然带 `Origin`，因此增加一条**同源**规则，而不是放开 CORS：

- `/studio/` 页面由伴侣程序自己提供，`Origin` 等于 `http://127.0.0.1:<端口>`；只放行这个同源值，其他 `Origin` 一律 401，仍然不发 CORS 头。
- 校验 `Host` 头必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`，防 DNS 重绑定。
- **用户不接触令牌**：伴侣程序在提供 `/studio/` 页面时（Host 校验通过后）下发会话 Cookie（`HttpOnly; SameSite=Strict; Path=/`）。跨站请求不会带上它，外站也读不到页面内容；`/api/*` 接受"同源 Origin + 会话 Cookie"或"无 Origin + 内部令牌"（CLI）两种方式。桌面版与浏览器形态走同一条路。
- 事件流 `/studio/events` 用 Server-Sent Events；同源 `EventSource` 会自动带上会话 Cookie，无需票据。

## 3. 信息架构与窗口布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ 标题栏：TavernCellar · 工作区名                     [● 酒馆连接摘要] │
├────┬─────────────┬──────────────────────────────────────┬────────────┤
│活动│ 侧栏         │ 编辑区（多标签）                      │ 检查栏      │
│栏  │              │ ┌ Alice ┐┌ 大陆设定 ┐                 │ 同步状态    │
│ 📚 │ 资料库 /     │                                      │ 每个酒馆一行│
│ 🗂 │ 工作区资料树 │   表单 / 条目列表 + 条目详情          │ 本项参数    │
│ 🔄 │              │                                      │ 文件位置    │
│ 🕘 │              │                                      │             │
│ ⚙ │              │                                      │             │
├────┴─────────────┴──────────────────────────────────────┴────────────┤
│ 状态栏：ST ● 已连接 · tt ○ 未连接 · 3 项有未同步修改 · 1 项冲突       │
└──────────────────────────────────────────────────────────────────────┘
```

| 活动栏 | 侧栏内容 | 说明 |
|---|---|---|
| 📚 资料库 | 选择酒馆 → 角色 / 世界书 列表 | 浏览酒馆里有什么，一键取出 |
| 🗂 工作区 | 已取出的资料树（角色、世界书，以后有正则、预设） | 日常编辑入口；每项带同步状态徽标 |
| 🔄 同步 | 全部"资料项 × 酒馆"的状态矩阵 | 批量同步、处理冲突 |
| 🕘 历史 | 版本记录（阶段 2 前显示说明占位） | |
| ⚙ 设置 | — | 打开设置标签页 |

- 编辑区为多标签，同一项只开一个标签；标签上显示"未保存到工作区"圆点（正常情况下几乎看不到，见 §5.1）与同步状态色条。
- 检查栏可折叠；窄窗口（< 1100px）时自动收起为抽屉，侧栏 < 800px 时收起为图标栏。
- 侧栏与检查栏的显示状态**按界面类型记忆**：世界书编辑与冲突处理需要宽度，默认收起侧栏，可用标签栏右侧的按钮打开。
- 全局快捷键：`Ctrl+P` 快速打开资料项、`Ctrl+S` 立即写入并（若为手动同步）弹出同步确认、`Ctrl+Shift+S` 同步当前项到全部已连接酒馆、`Ctrl+F` 当前编辑器内查找、`Ctrl+Shift+F` 世界书内全文查找。

## 4. 各界面

### 4.1 首次启动向导

三步，任何一步都可以"稍后再说"：

1. **选择工作区**：默认 `文档\TavernCellar`；可选已有文件夹（检测到 `cellar.json` 则直接打开）。
2. **安装 Cellar Link**：分 ST / tt 两个页签给出步骤——在酒馆"扩展 → 安装扩展"中填入仓库地址 `https://github.com/qianzhuowo/TavernCellar`。Studio **不**直接往酒馆数据目录里复制文件（遵守"只有 Cellar Link 写酒馆"，也避免在酒馆运行时动它的目录）。
3. **连接酒馆**：显示 `GET /api/detect` 的结果——ST / tt 各一张卡片：运行中 / 未运行 / 未检测到、Cellar Link 是否已安装、已连接 / 等待连接，以及"接受连接"开关（`POST /api/taverns`）与"重新检测"。无令牌：插件装好后自动连上；连上后可进入资料库。

### 4.2 资料库

- 顶部选择酒馆（下拉；只有一个连接时不显示）与类型（角色 / 世界书）。
- 角色以卡片网格显示（头像缩略图、名称、标签、最后聊天时间），世界书以列表显示（名称、条目数）；支持搜索、按名称 / 最近聊天排序；分页加载，滚动到底自动加载下一页。
- 已取出的项右上角显示"已在工作区"徽标，点击直接打开；未取出的项点击打开预览（只读摘要），按钮"取出到工作区"。
- 头像缩略图懒加载，经伴侣程序缓存（见 §6 `asset.get`）。

### 4.3 角色编辑

字段顺序与 ST 角色面板一致，分为主区与"高级定义"：

**主区**

| 区块 | 字段（ST 中文文案） | 卡片字段 |
|---|---|---|
| 头部 | 头像（只读预览，换头像在酒馆里做）、名称、标签（`嵌入的标签`，标签输入框）、收藏 | `data.name`、`data.tags`、`fav` |
| 角色描述 | 大文本框 | `data.description` |
| 第一条消息 | 大文本框 | `data.first_mes` |
| 其他开场 | 列表：每条一个可折叠文本框，可新增 / 删除 / 拖动排序，显示序号与首行预览 | `data.alternate_greetings` |

**高级定义**（默认折叠，展开状态按项记忆）

| 区块 | 字段 |
|---|---|
| 提示词覆盖 | 主要提示词（`system_prompt`）、后续历史指令（`post_history_instructions`）；提示可插入 `{{original}}` |
| 角色设定 | 角色设定摘要（`personality`）、情景（`scenario`）、对话示例（`mes_example`，提示每段以 `<START>` 开头） |
| 角色备注 | 文本 + `@ 深度` 数字 + `角色`（系统 / 用户 / 助手）（`extensions.depth_prompt`） |
| 创作者的元数据 | 创作者、角色版本、创作者的注释（"不随 AI 提示词发送"） |
| 群聊 | 发言频率（低 / 正常 / 高 滑块，`extensions.talkativeness`） |
| 世界书 | 主要知识书（`extensions.world`）：下拉选择工作区中的世界书与该卡所在酒馆中的世界书，可清除；选中的书不在工作区时提供"一起取出"，已在工作区时可跳转。绑定写进卡片，随卡片同步 |
| 其他字段 | 只读折叠区：列出卡片中 Studio 没有专门表单的字段（如 `extensions` 下其他插件的数据），说明"原样保留，可在 card.json 中编辑" |

- 每个文本框底部显示字数（阶段 5 有了 Cellar Link 的分词器后改为"词符"数）。
- 文本框可"展开编辑器"占满编辑区，支持 `{{char}}`、`{{user}}` 等宏的高亮（CodeMirror 阶段）。
- 宿主在 `merge-attributes` 语义下无法删除字段：清空某字段时提示"酒馆会保留原值以外的内容……"，与伴侣程序的警告一致。

### 4.4 世界书编辑

三栏：条目列表 | 条目详情 |（检查栏）

**条目列表**（虚拟列表，数千条目也流畅）

- 每行：状态灯（🔵 永久 / 🟢 关键词 / 🔗 向量化，即 `constant` / 普通 / `vectorized`）、启用开关（`disable` 取反）、条目标题/备忘录（`comment`）、主要关键字（前几个，chip）、位置简写（↑Char、↓Char、↑EM、↓EM、↑AN、↓AN、@D⚙/👤/🤖、➡️Outlet）、深度、顺序、触发 %。
- 顶部：搜索（标题、关键字、内容）、筛选（状态、位置、启用、包含组）、排序（与 ST 一致：优先级、自定义、标题 A-Z / Z-A、字数 ↗↘、深度 ↗↘、顺序 ↗↘、UID ↗↘、触发% ↗↘）+ "按组显示"开关（见下方"条目分组"）。
- 多选（Shift / Ctrl）后显示批量操作条：启用 / 停用、改位置、改顺序（设为值 / 加减）、改深度、改触发 %、设包含组、移入组 / 移出组、删除。
- 新建条目套用酒馆的条目模板（伴侣程序保存的 `.cellar/templates/worldinfo-entry.json`），uid 由伴侣程序分配；复制条目生成新 uid。
- 拖动随排序方式："自定义"排序下拖动修改显示顺序 `displayIndex`（不影响提示词，与 ST 的自定义排序一致）；"顺序"排序下拖动修改 `order`（顺序值决定插入优先级），拖动时提示新的顺序值；其他排序下不可拖动。

**条目分组**（Cellar 自有功能，酒馆不认识，只原样保存）

- 组记在条目上：`extensions.cellar.group`，值为组路径字符串（如 `世界背景/地理`，为多级分类预留；第一版界面只用一级）。没有组的条目不写该字段。组由其中的条目定义，不另存组列表；新建的空组只在界面中暂存，放入条目后才存在。
- 工作区中组就是 `entries/` 下的子文件夹：`entries/世界背景/0003-龙脊山脉.md`。文件夹是唯一来源，文件头里不重复写组；在 VS Code 中把文件移到别的文件夹即换组。
- **同组同位置**：同一组的条目插入位置（`position`）相同，深度、顺序等可以不同。组标题显示该位置；把条目放进组时按组的位置修改条目位置（先提示将改动的条目）；组内位置不一致（在 VS Code 或酒馆中改过）时显示"位置不一"和"统一"按钮，不擅自改写。
- **整组操作**（执行前都提示影响多少条目、改成什么值）：
  1. 改插入位置：组内全部条目改为新位置；改为 @D 时没有深度的条目使用默认深度。
  2. 改顺序：整组设为一段区间（保留组内相对先后）或整体加减。
  3. 改显示顺序："自定义"排序下拖动整组，只改 `displayIndex`。
  4. 改名、解散（条目回到无组）。
- **按组显示**：组为可折叠分区，组内按所选排序；组之间按自定义顺序（组内最小 `displayIndex`）或组名排列；无组条目排在最后的"未分组"分区。关闭时为平铺列表，行内显示组名 chip。

**条目详情**（字段顺序与 ST 条目编辑面板一致）

| 区块 | 字段 |
|---|---|
| 标题行 | 条目标题/备忘录、状态（永久 / 关键词 / 向量化）、启用 |
| 关键字 | 主要关键字（chip 输入，支持 `/正则/`）、逻辑（与任意 / 与所有 / 非所有 / 非任何）、可选过滤器（`keysecondary`） |
| 插入 | 位置、深度（仅 @D 时）、顺序、触发 %（`probability` + 使用概率）、Outlet 名称（仅 ➡️Outlet 时） |
| 内容 | 大文本框（主体，占剩余高度），字数统计 |
| 高级（折叠） | **递归**：不可递归、防止进一步递归、延迟到递归 + 递归等级；**分组**：包含组、确定优先级、组权重、组评分；**时效**：黏性、冷却、延迟；**扫描**：扫描深度（"使用全局设置 / 自定义 + 数值"）、区分大小写、完整单词（后两项为"使用全局设置 / 是 / 否"三态）；**额外匹配来源**：角色描述、角色性格、情景、用户设定描述、角色备注、创作者的注释；**筛选**：绑定到角色或标签 + 排除、筛选生成触发器（正常 / 继续 / AI 帮答 / 滑动 / 重新生成 / 静默）；**其他**：选择性、无视回复限额、自动化 ID、添加备忘录 |

- 三态字段（`null` = 使用全局设置）必须如实保留 `null`，不能被表单默认成 `false`。
- 书级设置（`book.json` 中条目以外的字段）放在列表顶部的"书设置"折叠区；未识别字段只读展示。

### 4.5 同步与冲突

**同步面板**（活动栏 🔄，也嵌在每项的检查栏里）

- 矩阵：行 = 工作区资料项，列 = 酒馆。单元格显示状态：
  - ✓ 已同步｜● 本地有修改（待同步）｜↓ 酒馆有修改（工作区有改动未拉取时）｜⚠ 冲突｜— 未绑定｜○ 酒馆未连接
- 单元格操作：同步、取回、随时同步开关（即"保存即同步"）、解除绑定。
- 顶部："同步全部本地修改到 [酒馆]"、"只看有问题的项"。
- 伴侣程序返回的警告（如"酒馆保留了已删除的字段"）以通知条显示在对应项上，可展开看涉及的字段路径。

**冲突处理**（打开冲突项时编辑区顶部出现横幅，点"处理冲突"进入对比视图；检查栏的冲突提示、同步矩阵和对冲突项点"同步/取回"也会打开它）

- **按槽位对比**，而不是按文件：伴侣程序按槽位（字段、开场白、世界书条目……与编解码器同一份定义）三方比对，只列出两边都改了的槽位。每个槽位一行：左 = 工作区，右 = 酒馆，可打开"显示基准版本"；长文本显示行内差异（相对基准；没有基准时工作区相对酒馆），条目等对象只列出两边不同的属性，其余显示 JSON。
- 每个槽位可选"用工作区 / 用酒馆 / 手动合并"（手动合并打开可编辑的合并框，对象以 JSON 编辑）；某一边删除了该槽位时按钮显示为"删除（同工作区/酒馆）"。世界书条目本身就是槽位，新增 / 删除的条目同样以"有 / 无"列出。
- 冲突界面打开时所有槽位均为未选定；可"全部用工作区 / 全部用酒馆"。一项有多个冲突酒馆时可在顶部切换。
- **整项冲突**：在启用按字段合并之前同步过的项没有基准快照，冲突记为整项（`*`），只能整项选择一边；界面列出两边不同的各个槽位供参考。解决后保存基准，之后的冲突按槽位列出。
- 全部选定后"应用并同步"：伴侣程序写入工作区，以界面看到的酒馆版本为新基准，再走正常同步（重新读取酒馆，若酒馆期间又改了别处则自动合并，又改了同一处则重新报冲突）；完成后关闭冲突页回到资料项。

### 4.6 设置

- 工作区：当前路径、切换 / 新建、在资源管理器中打开。
- 连接：端口；各酒馆的检测结果与"接受连接"开关；已连接酒馆列表（名称、来源 Origin）。无令牌。

- 外部编辑器：命令（默认 `code`），用于"在 VS Code 中打开"。
- 应用（仅桌面版）：开机启动、关闭窗口时最小化到托盘、自动检查更新。

## 5. 交互与状态

### 5.1 保存模型

- 表单修改在 400ms 无输入后**自动写入工作区**（等同于在 VS Code 里按保存）；界面不设"保存"按钮，标签页圆点只在写入进行中或失败时出现。
- 写入工作区后，若该项对某酒馆开启了随时同步，伴侣程序自动推送；否则该酒馆单元格变为"● 本地有修改"。
- 撤销 / 重做按标签页保存在内存中，覆盖自动写入（撤销会再次写入工作区）。

### 5.2 外部修改

- 伴侣程序通过事件流推送"工作区文件变化"与"酒馆端变化"。
- 打开中的项被外部修改时：若 Studio 没有尚未写入的输入，直接刷新（保留光标所在字段与滚动位置）；若正在输入，先写入 Studio 的修改，伴侣程序按 `baseHash` 判断，产生冲突时走冲突流程。
- 外部写入了无法解析的文件（例如 YAML 写坏）：该项显示"文件无法解析"横幅，指出文件与行号，暂停表单编辑，直到文件修好。

### 5.3 连接状态

- 状态栏常驻每个酒馆的连接点；断开时编辑不受影响，同步按钮置灰并提示"酒馆未连接"。
- 伴侣程序本身不可达（浏览器形态下）时全屏遮罩"无法连接 TavernCellar，正在重试…"。

### 5.4 空状态与错误

每个列表都有空状态说明与下一步按钮（如"还没有取出任何资料 → 去资料库"）；错误通知包含可复制的详细信息。

## 6. 伴侣程序需要新增的接口

Studio 只调用伴侣程序；以下接口在实现 Studio 时加入，命令行同样可以使用。

| 接口 | 作用 |
|---|---|
| `GET /studio/`（静态文件） | 提供界面并下发会话 Cookie；同源规则与 `Host` 校验见 §2.3 |
| `GET /studio/events` | SSE 事件流：`target.connected/disconnected`、`item.local-changed`（文件监视）、`item.tavern-changed`、`item.status`（同步状态变化）、`item.warning`、`item.conflict` |
| `GET /api/detect`、`POST /api/taverns` | （已实现）检测本机酒馆、选择接受哪类酒馆的连接 |
| `GET /api/items` | 工作区资料项列表 + 每个绑定的状态（现有 `/api/status` 的细化） |
| `POST /api/item` | `{path}` → 一项的**结构化数据**（解码后的卡片 / 世界书 JSON）+ 工作区哈希；世界书另附新条目模板 `entryTemplate` |
| `PUT /api/item` | `{path, data, hash}` → 编码写入工作区文件；工作区哈希不符（文件在别处被改）返回 `conflict`，`details.hash` 为当前哈希 |
| `POST /api/item/entries` | 世界书条目级修改（大世界书避免整本往返）：`{path, hash, ops}`，op 为 `{op:'set', uid, patch, unset?}` / `{op:'create', entry?}` / `{op:'delete', uid}`；批量操作与组操作都是一组 ops，一次写入；新建条目套模板、uid 由伴侣程序分配并排在显示顺序最后 |
| `GET /api/items/:path/conflict?target=` | 冲突详情：冲突槽位列表，每个槽位含工作区 / 酒馆 / 基准三方的值（`{value, present}`）与可读标签；整项冲突附两边不同的槽位 `differences` |
| `POST /api/items/:path/resolve` | `{target, choices: {槽位: 'workspace' \| 'tavern' \| {value}}}` 逐槽位提交选择：写入工作区、以所见酒馆版本为基准并同步；必须覆盖全部冲突槽位 |
| `GET /api/assets/avatar?target=&id=` | 角色头像缩略图；伴侣程序经新的协议消息 `asset.get` 请 Cellar Link 读取 `/thumbnail`，按目标 + 文件名 + 修改时间缓存 |
| `GET/PUT /api/settings`、`POST /api/workspace` | 设置、工作区切换 |

协议变更：增加 `asset.get` 消息（插件读取头像缩略图并以 base64 返回，单次大小上限 512KB）；`PROTOCOL_VERSION` 保持 1，新消息对旧插件返回 `bad_request` 时界面显示占位头像。

编码规则不变：结构化数据 ⇄ 文件的转换只在伴侣程序的编解码层发生，Studio 不直接读写工作区文件。

## 7. 视觉方向

- **气质**："酒窖"——沉稳、温暖、安静，适合长时间读写长文本；不做花哨动效。
- **深色主题（默认）**：底色深木炭（#17140f 一类，略带暖调），面板分层用 2–3 级明度；强调色为酒红（用于主按钮、选中态），辅以琥珀（警告 / 本地修改）与橄榄绿（已同步）；冲突用醒目的砖红。
- **浅色主题**：羊皮纸米白底、深褐文字，强调色同色相加深。
- **状态色语义固定**：已同步 = 绿、本地有修改 = 琥珀、酒馆有修改 = 蓝、冲突 = 红、未连接 = 灰；同时配图标，不只靠颜色区分。
- **字体**：界面用系统字体（Windows 下 "Microsoft YaHei UI" / "Segoe UI"）；正文编辑区可选无衬线（思源黑体 / 系统）、衬线（思源宋体，适合读长段落）、等宽；uid、路径用等宽。
- **密度**：两档（紧凑 / 舒适），默认舒适；世界书列表行高 紧凑 32px / 舒适 40px。
- **图标**：Lucide 线性图标，状态灯沿用酒馆的 🔵🟢🔗 语义但用自绘圆点以保证跨平台一致。

## 8. 技术选型建议

| 项 | 建议 | 备选 / 理由 |

| 桌面外壳 | Electron（已定） | 伴侣程序是 Node，可在主进程内直接运行，一个进程一套语言 |

| 更新 | electron-updater + GitHub Releases | |
| 代码签名 | 初期不签名（SmartScreen 会提示），用户量起来后再购买证书 | 发布说明中写明校验方法（SHA-256） |
